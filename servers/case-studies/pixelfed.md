# Pixelfed 0.15.2

Pixelfed is a media-first social server with local applications, client APIs and ActivityPub federation. A post can cross SQL, Redis, media storage, worker queues and remote servers before it appears in another user's feed. This case study concerns [Pixelfed 0.15.2](../../references/software/pixelfed.md); it is a pinned source study, not a running-server or interoperability test.

## Architecture

The server uses PHP and Laravel. The supplied deployment separates the web runtime, Horizon queue workers, scheduler, SQL database and Redis. Media and derivatives live in a filesystem or object storage, while their metadata stays in SQL. Backups and recovery must account for the database, application secrets and media together; Redis also contains queues and feed state, so treating it as disposable can lose pending work. `[source]` [dependencies](https://github.com/pixelfed/pixelfed/blob/b19607f1315b45aead25bc827c5e691a62317894/composer.json), [Compose](https://github.com/pixelfed/pixelfed/blob/b19607f1315b45aead25bc827c5e691a62317894/docker-compose.yml), [queue configuration](https://github.com/pixelfed/pixelfed/blob/b19607f1315b45aead25bc827c5e691a62317894/config/horizon.php), [filesystems](https://github.com/pixelfed/pixelfed/blob/b19607f1315b45aead25bc827c5e691a62317894/config/filesystems.php).

The README describes MySQL/MariaDB as the primary database path and PostgreSQL as best effort; do not infer identical migrations or query behavior. `User` is a local login principal; `Profile` represents local or remote actors. `Status` stores visibility, relationships and remote object references; attached media has separate metadata and files. `[source]` [README](https://github.com/pixelfed/pixelfed/blob/b19607f1315b45aead25bc827c5e691a62317894/README.md), [Profile](https://github.com/pixelfed/pixelfed/blob/b19607f1315b45aead25bc827c5e691a62317894/app/Models/Profile.php), [Status](https://github.com/pixelfed/pixelfed/blob/b19607f1315b45aead25bc827c5e691a62317894/app/Models/Status.php).

## Key code paths

### Incoming activity

1. Federation routes accept individual or shared inbox deliveries and dispatch background work. The HTTP response is a receipt, not proof that validation, status creation and media processing finished. `[source]` [routes](https://github.com/pixelfed/pixelfed/blob/b19607f1315b45aead25bc827c5e691a62317894/routes/api.php), [controller](https://github.com/pixelfed/pixelfed/blob/b19607f1315b45aead25bc827c5e691a62317894/app/Http/Controllers/FederationController.php).
2. The inbox validator checks the signature and key identity against the claimed activity actor before using an activity-ID deduplication cache. Object URLs, domain policy and object attribution have separate validation paths. `[source]` [validator](https://github.com/pixelfed/pixelfed/blob/b19607f1315b45aead25bc827c5e691a62317894/app/Jobs/InboxPipeline/InboxValidator.php#L57), [incoming handler](https://github.com/pixelfed/pixelfed/blob/b19607f1315b45aead25bc827c5e691a62317894/app/Jobs/InboxPipeline/ActivityHandler.php).
3. The dispatcher routes recognized verbs to specialized handlers. A supported `Create` can store a remote status and schedule feed and media work; unsupported objects do not automatically obtain native behavior. `[source]` [inbox dispatch](https://github.com/pixelfed/pixelfed/blob/b19607f1315b45aead25bc827c5e691a62317894/app/Util/ActivityPub/Inbox.php), [Create handler](https://github.com/pixelfed/pixelfed/blob/b19607f1315b45aead25bc827c5e691a62317894/app/Util/ActivityPub/Inbox/HandlesCreates.php).
4. A reply whose remote parent cannot yet be resolved can be parked and retried instead of being silently made a root post. The retry schedule in the relevant job includes 180, 900, 3,600 and 21,600 seconds; exhausting it does not prove the parent never existed. `[source]` [reply resolution job](https://github.com/pixelfed/pixelfed/blob/b19607f1315b45aead25bc827c5e691a62317894/app/Jobs/StatusPipeline/RemoteReplyResolvePipeline.php).

`[hypothesis]` The time-limited deduplication guard and a failure after it is set may suppress a later retry before durable completion. Test by interrupting the handler after acquiring the key, replaying the same activity ID, and checking SQL and queue state; this is not a demonstrated incident. `[source]` [validator](https://github.com/pixelfed/pixelfed/blob/b19607f1315b45aead25bc827c5e691a62317894/app/Jobs/InboxPipeline/InboxValidator.php#L57), [activity job](https://github.com/pixelfed/pixelfed/blob/b19607f1315b45aead25bc827c5e691a62317894/app/Jobs/InboxPipeline/ActivityHandler.php).

### Outgoing and local feeds

A local status is persisted, entities are processed, and a federation job selects eligible remote followers, mentions and reply targets. Shared inboxes can reduce duplicate destinations; fan-out chunks destinations into background jobs, which sign and send HTTP requests. The default chunk size is 50 inboxes; an enqueued chunk is not a journal proving each recipient applied the post. `[source]` [status processing](https://github.com/pixelfed/pixelfed/blob/b19607f1315b45aead25bc827c5e691a62317894/app/Jobs/StatusPipeline/StatusEntityLexer.php), [recipient selection](https://github.com/pixelfed/pixelfed/blob/b19607f1315b45aead25bc827c5e691a62317894/app/Jobs/StatusPipeline/StatusActivityPubDeliver.php), [fan-out](https://github.com/pixelfed/pixelfed/blob/b19607f1315b45aead25bc827c5e691a62317894/app/Services/ActivityPubFanoutService.php), [chunk job](https://github.com/pixelfed/pixelfed/blob/b19607f1315b45aead25bc827c5e691a62317894/app/Jobs/Federation/DeliverActivityChunk.php).

Home timeline indexes use Redis sorted sets and a bounded cache; the home service warms a replacement set before publishing it. Cursor handling compensates for stale entries and precision problems around large numeric IDs. SQL remains essential for object hydration and durable social records; a cache hit alone does not establish current visibility. `[source]` [home timeline](https://github.com/pixelfed/pixelfed/blob/b19607f1315b45aead25bc827c5e691a62317894/app/Services/HomeTimelineService.php), [sorted-set cursor logic](https://github.com/pixelfed/pixelfed/blob/b19607f1315b45aead25bc827c5e691a62317894/app/Services/Concerns/SortedSetTimeline.php), [status policy](https://github.com/pixelfed/pixelfed/blob/b19607f1315b45aead25bc827c5e691a62317894/app/Services/StatusService.php).

## API coverage

Pixelfed supplies first-party web and mobile-facing endpoints as well as a Mastodon-shaped API subset. A route's existence does not establish equivalent authorization, pagination or full Mastodon semantics. The normal status creation implementation has media-first constraints, including restrictions on text-only root posts and `direct` visibility; consult and test the exact endpoint rather than assume all Mastodon options work. `[source]` [API controller](https://github.com/pixelfed/pixelfed/blob/b19607f1315b45aead25bc827c5e691a62317894/app/Http/Controllers/Api/ApiV1Controller.php), [API routes](https://github.com/pixelfed/pixelfed/blob/b19607f1315b45aead25bc827c5e691a62317894/routes/api.php).

## Federation behaviour

The release implements ActivityPub server-to-server, WebFinger, NodeInfo and draft HTTP signatures. Incoming `Create`, `Update`, `Delete`, `Follow`, `Like`, `Announce`, `Undo`, `Move` and reporting paths have specific object and permission checks, not a generic interpreter for every valid activity. The actor and note serializers emit Pixelfed and other extensions; a peer may discard metadata it does not understand. `[source]` [federation routes](https://github.com/pixelfed/pixelfed/blob/b19607f1315b45aead25bc827c5e691a62317894/routes/api.php), [inbox](https://github.com/pixelfed/pixelfed/blob/b19607f1315b45aead25bc827c5e691a62317894/app/Util/ActivityPub/Inbox.php), [actor serializer](https://github.com/pixelfed/pixelfed/blob/b19607f1315b45aead25bc827c5e691a62317894/app/Transformer/ActivityPub/ProfileTransformer.php).

The source includes quote approval, follower synchronization and block synchronization mechanisms associated with FEP-044f, FEP-8fcf and FEP-070c. These are separate protocol paths and do not prove full interoperability with any particular peer; configuration and object state affect them. `[source]` [quote service](https://github.com/pixelfed/pixelfed/blob/b19607f1315b45aead25bc827c5e691a62317894/app/Services/QuoteService.php), [follower synchronization](https://github.com/pixelfed/pixelfed/blob/b19607f1315b45aead25bc827c5e691a62317894/app/Services/FollowersSyncService.php), [block synchronization](https://github.com/pixelfed/pixelfed/blob/b19607f1315b45aead25bc827c5e691a62317894/app/Services/BlockSyncService.php).

An important limit for history consumers: the tagged outbox implementation exposes a recent public slice and indicates that pagination is unsupported. It should not be treated as a complete export of an actor's post history. `[source]` [outbox](https://github.com/pixelfed/pixelfed/blob/b19607f1315b45aead25bc827c5e691a62317894/app/Util/ActivityPub/Outbox.php).

## Security, privacy and operations

Signature verification, actor ownership, outbound URL validation and media fetching cross distinct trust boundaries. The signed fetch and media services validate remote destinations; deployments should still test redirects, DNS changes, private addresses and oversized responses. Followers-only visibility depends on local authorization and peer handling: sending content to a remote server cannot force that peer to erase its copy later. `[source]` [fetch service](https://github.com/pixelfed/pixelfed/blob/b19607f1315b45aead25bc827c5e691a62317894/app/Services/ActivityPubFetchService.php), [secure media fetch](https://github.com/pixelfed/pixelfed/blob/b19607f1315b45aead25bc827c5e691a62317894/app/Services/SecureMediaFetchService.php), [status access](https://github.com/pixelfed/pixelfed/blob/b19607f1315b45aead25bc827c5e691a62317894/app/Services/StatusService.php).

Queue backlog, SQL, Redis and media storage need independent monitoring. Restore tests should include schema version, environment secrets, media files and object storage, then verify feed rebuilding and pending jobs in isolation. The implementation has maintenance and warmup paths; no general automatic repair of arbitrary database corruption is established. `[source]` [scheduler](https://github.com/pixelfed/pixelfed/blob/b19607f1315b45aead25bc827c5e691a62317894/bootstrap/scheduledtasks.php), [home timeline](https://github.com/pixelfed/pixelfed/blob/b19607f1315b45aead25bc827c5e691a62317894/app/Services/HomeTimelineService.php).

## Resource usage and tradeoffs

No memory, CPU, database size, throughput or recovery-time measurements were made. Media processing and retained assets, distinct remote inboxes, queue concurrency and feed cache sizes are dimensions to measure under an explicit workload. The framework and job separation support modular async processing, but introduce multiple failure boundaries that require monitoring and replay tests. `[source]` [delivery service](https://github.com/pixelfed/pixelfed/blob/b19607f1315b45aead25bc827c5e691a62317894/app/Services/ActivityPubDeliveryService.php), [Horizon configuration](https://github.com/pixelfed/pixelfed/blob/b19607f1315b45aead25bc827c5e691a62317894/config/horizon.php).

## Technical details

Test with pinned software and fixture accounts: signed `Create` through personal and shared inboxes, invalid actor/key binding, duplicate delivery after a worker failure, reply before parent, inaccessible media, cold timeline warming and delivery to several followers on one remote host. Capture full redacted requests, job outcomes and final SQL/API state. No live result is asserted here.
